# Кино-эссе: 5-актная аналитическая структура и план эссе

Дата: 2026-10-27
Статус: утверждено к реализации

## Задача

`essays_20_films.md` — это ТЗ на структуру эссе, а не список фильмов для хардкода. Нужен общий механизм, который для любого фильма:

1. строит аналитическую драматургию: хук/экспозиция → форма → психология → философия → катарсис;
2. предлагает 2–3 варианта хука; пользователь выбирает или вводит свой;
3. сам раскладывает сцены по актам (роли), а не по четвертям хронометража фильма;
4. укладывается в выбранный хронометраж (8/10/12/15 мин, дефолт — 520 с);
5. показывает хук карточкой в начале, CTA — в финале, и переносит оба в метаданные.

Правило «никакого per-film hardcode» сохраняется: названия фильмов в промпт и код не попадают, md используется как описание структуры и примеры.

## Решения

- **Актов 5, только для LLM-пути**: `hook`, `form`, `psychology`, `philosophy`, `catharsis`.
- Эвристический fallback (LLM недоступен) остаётся 4-актным и байт-идентичным: старые типы `downfall`/`struggle` сохраняются в enum как legacy.
- Тема по-прежнему выбирается Director'ом (`.llm`). Хук может быть выбран из предложенных моделью или введён вручную; у хука собственный источник (`llm`/`manual`), правило авторства темы не меняется.
- Сцены выбирает Director; ручное перекидывание сцен между актами в этот раунд не входит (следующий этап).
- Акт «форма» не получает видеоряд: в промпт добавляется запрет выдумывать конкретные визуальные детали без данных; формулировки — о структуре, монтаже и ритме, выводимых из материала.

## Модель данных

### `LongformActType` (расширение)

Новые case: `form = "Анализ формы"`, `psychology = "Психология героя"`, `philosophy = "Философский подтекст"`.
Старые rawValue не меняются (совместимость архивов).

- `canonicalAnalyticOrder = [.hook, .form, .psychology, .philosophy, .catharsis]`
- `promptKey`: `hook|form|psychology|philosophy|catharsis|downfall|struggle` для парсинга ответов модели.
- `targetDurationRatio`: hook 0.12, form 0.24, psychology 0.26, philosophy 0.24, catharsis 0.14. Старые значения не меняются.

### `EssayPlan`

```swift
struct EssayPlan: Codable, Equatable, Sendable {
    struct TextVariant: Codable, Equatable, Sendable, Identifiable {
        var id: String { text }
        let text: String
        var source: ThematicSource   // .llm / .manual
    }
    var thesis: String?
    var hookVariants: [TextVariant]
    var selectedHook: TextVariant?
    var ctaVariants: [TextVariant]
    var selectedCTA: TextVariant?
    var targetDuration: Double?
    var actFocus: [String: String]   // promptKey -> что доказывает акт
}
```

Декодируется терпимо: все поля `decodeIfPresent`, отсутствие = старый архив.

### `SelectedMoment`

Добавляются опциональные поля: `actRole: LongformActType?`, `supports: String?`, `featured: Bool?` (nil = false). Старые архивы читаются.

### `ThematicAnalysisResult`

Добавляется `essayPlan: EssayPlan?`; кодируется/декодируется опционально.

### `LongformNarrativeArc`

Добавляются опциональные `hookText`, `ctaText`, `thesis` — их читают рендер и генератор метаданных, они переживают персист.

## Промпты и парсинг

### Director (один проход)

Схема ответа расширяется:

```json
"essayPlan": {
  "thesis": "...",
  "hookVariants": ["...", "...", "..."],
  "ctaVariants": ["...", "..."],
  "actFocus": { "form": "...", "psychology": "...", "philosophy": "...", "catharsis": "..." }
},
"selectedMoments": [
  { "startTime": 1, "endTime": 2, "reason": "...", "dramaticWeight": 0.9,
    "actRole": "hook|form|psychology|philosophy|catharsis",
    "supports": "...", "featured": true }
]
```

В системный промпт добавляется раздел структуры: порядок удержания, требования к хуку (1–2 предложения, вопрос/парадокс, без пересказа финала), требование к фокусу каждого акта и к связи сцены с тезисом акта; запрет выдумывать визуальные детали. Примеры структуры — без названий фильмов.

Парсер терпим к строке/объекту в `hookVariants`/`ctaVariants`, к отсутствию `essayPlan` (тогда поведение прежнее).

### Названия актов (второй проход)

`parseActTitleProposals(from:)` получает параметр `expectedTypes` (по умолчанию старый 4-актный список) и принимает ровно `expectedTypes.count` строк в этом порядке. `applyTitles` передаёт фактические типы арки. Промпт строится динамически по типам арки; для 5 актов — пять описаний.

## Сборка арки

`buildArc(... essayPlan:)`:

1. Если среди моментов есть роли и покрыто ≥3 из 5 ролей — аналитическая арка:
   - моменты без роли распределяются в наименее заполненный акт;
   - каждый акт получает хотя бы один момент (перенос из соседнего с >1);
   - добор до выбранного хронометража: акт получает свою долю (`analyticDurationRatio`), недостача закрывается расширением выбранных сцен соседним непрерывным диалогом (`sceneGapLimit`, не больше 120 с на сцену), а если рядом пауза — ближайшими неиспользованными диалоговыми кусками (≤600 с от сцены). Это деградация в эвристику: тема и акты остаются от модели;
   - лишнее режется целыми моментами: сначала `featured = false` с минимальным `dramaticWeight`, пока сумма ≤ `targetDuration × 1.10`;
   - акты в каноническом порядке; `dramaticBeat` = фокус акта из плана или `reason` первого момента.
2. Иначе — прежняя 4-актная раскладка по квартилям (совместимость и старые кэши).
3. В арку пишутся `hookText`/`ctaText`/`thesis` из выбранного плана.
4. Клэмп целевого хронометража: 300…900 с (было 300…600).
5. Директор возвращает 16–24 сцены по 20–60 с с запасом 720–900 с: выбранный хронометраж — обязательство, а не только потолок. Если модель вернула меньше, арка добирает материал сама.

## Пайплайн и UI

- `LongformPipelineCoordinating.buildLongformVideo` получает `essayPlan: EssayPlan?`; координатор передаёт его в `buildArc` и берёт `targetDuration` из плана (дефолт 520).
- `WorkspaceModel.confirmLongformConcept` принимает `essayPlan`, сохраняет его в `ThematicAnalysisResult.essayPlan` (персист через `persistThemeState`), прокидывает в сборку и в редактор субтитров.
- `ThematicConceptSelectionSheet`: секция «Хук» (3 карточки + поле своего текста) и пресет длительности 8/10/12/15 мин (по умолчанию 11 мин). `onSelect` получает `EssayPlan`.
- Значения по умолчанию: если пользователь ничего не выбрал — первый вариант хука модели; CTA — первый вариант.

## Рендер

- `makeOverlayLayer` получает `hookText` и `ctaText`.
- Вступительный слой: если `hookText` есть — показывает его 0–6 с (до 3 строк); иначе прежний tagline 0–4.2 с.
- Субтитры скрываются до 6.2 с при хуке, иначе до 4.5 с (параметризовать существующие константы).
- CTA-карточка: последние ~4 с, тот же кино-стиль (Russo One, акцентная линия), плавное появление/затухание; пустой CTA — слоя нет.
- Карточки актов уже generic: 5 актов, нумерация по индексу.

## Метаданные

- Описание: хук и тезис (если есть) вместо/перед текущими абзацами.
- Закреплённый комментарий: `ctaText`, если задан; иначе прежний текст.
- Главы: generic по числу актов (уже так).

## Совместимость

- Старые архивы: enum rawValue не меняются, новые поля опциональные, старые 4-актные арки не пересобираются.
- Старые кэши анализа без `essayPlan` работают по прежней схеме (4 акта, tagline).
- Эвристический fallback не меняется.

## Вне рамок этого раунда

- Интерактивный выбор/перекидывание сцен между актами.
- Grounding акта «форма» статистикой `SceneDetectionService` (длина планов, частота склеек).
- Shorts/TikTok-сцена из плана.

## Тестирование

Новое:
- парсинг `essayPlan` (полный/частичный/старый ответ);
- сборка 5 актов по ролям, перенос моментов, бюджет и `featured`;
- 5-актное титлование (`expectedTypes`);
- рендер: слой хука и CTA присутствуют/отсутствуют; субтитры не лезут под хук;
- персист плана и хука.
